# Dispatch Engine

## 배차 원칙
- 가장 먼저 고려하는 기준은 `고객 대기 시간 최소화`다.
- 배차는 항상 `가용 기사`와 `가용 차량`만 대상으로 한다.
- 동일 조건에서는 `예상 도착 시간(ETA)`이 짧은 기사를 우선한다.
- 장거리 공차, 반복 재배차, 이미 과부하 상태인 기사 배정은 불리하게 평가한다.
- VIP, 예약, SLA 임박 오더는 일반 오더보다 높은 우선순위를 가진다.
- 자동 배차 실패 시 즉시 수동 개입이 가능하도록 상태를 명확히 남긴다.

## 기사 상태
- `OFFLINE`: 앱 미접속 또는 근무 종료 상태, 배차 불가
- `IDLE`: 배차 가능 상태
- `RESERVED`: 특정 오더에 임시 홀딩된 상태
- `DISPATCHED`: 배차 확정, 픽업 이동 중
- `ON_TRIP`: 고객 탑승 후 운행 중
- `RESTING`: 휴식 또는 강제 비가용 상태
- `SUSPENDED`: 정책 또는 운영 이슈로 배차 제외 상태

## 오더 상태
- `CREATED`: 오더 생성 직후
- `WAITING`: 배차 후보 탐색 중
- `RECOMMENDED`: 추천 기사 목록이 생성된 상태
- `DISPATCHING`: 특정 기사에게 제안 또는 확정 진행 중
- `DISPATCHED`: 기사 배정 완료
- `PICKING_UP`: 기사 픽업 이동 중
- `ON_TRIP`: 운행 진행 중
- `COMPLETED`: 운행 종료
- `CANCELLED`: 고객 또는 운영 취소
- `FAILED`: 자동 배차 실패, 수동 개입 필요

## 이동시간 계산
- 이동시간은 우선적으로 지도 API 또는 라우팅 엔진의 ETA 값을 사용한다.
- 실시간 ETA가 없으면 직선거리 기반 추정치로 임시 계산한다.
- 계산 기준
  - 기사 현재 위치 -> 출발지 ETA
  - 출발지 -> 목적지 ETA
  - 교통량, 시간대, 날씨, 도로 통제 여부 반영 가능
- ETA는 일정 주기로 재계산하며, 오래된 위치 정보는 신뢰도를 낮춘다.

## 우선순위
- 기본 우선순위는 아래 순서로 평가한다.
1. SLA 임박 여부
2. 예약/시간 지정 여부
3. VIP 또는 우선 고객 여부
4. 오더 생성 시각
5. 픽업 ETA
6. 기사 점수
- 같은 우선순위라면 더 빨리 도착 가능한 기사에게 배차한다.

## 충돌 검사
- 같은 기사에게 동시에 두 개 이상의 활성 오더를 배정하지 않는다.
- 이미 `RESERVED`, `DISPATCHED`, `ON_TRIP` 상태인 기사는 중복 배차에서 제외한다.
- 차량 단위 제약이 있다면 동일 차량도 중복 점유되지 않도록 검사한다.
- 기사 위치 정보가 너무 오래되었거나, 최근 상태 변경과 충돌하면 후보에서 제외한다.
- 예약 오더와 일반 오더가 겹칠 경우 예약 오더를 우선 보호한다.

## 추천 기사
- 추천 기사는 단일 확정 전에 생성되는 후보군이다.
- 후보 생성 절차
1. 반경 또는 행정구역 기준으로 가용 기사 조회
2. 기사 상태 및 충돌 여부 검사
3. ETA, 기사 점수, 최근 취소율, 공차 거리로 점수 계산
4. 상위 N명을 추천 목록으로 생성
- 추천 목록은 운영자 수동 선택 또는 자동 확정에 모두 사용 가능하다.

## WAITING Queue
- 자동 배차 즉시 확정이 어려운 오더는 `WAITING Queue`에 넣는다.
- WAITING Queue 진입 조건
  - 가용 기사 없음
  - ETA 기준 미달
  - 정책 충돌
  - 추천 기사 응답 실패
- 대기열 오더는 재시도 주기에 따라 다시 후보를 탐색한다.
- 일정 시간 이상 대기 시 운영자에게 경고 또는 수동 배차 알림을 보낸다.

## 자동 재배차
- 다음 상황에서 자동 재배차를 수행할 수 있다.
  - 기사가 제한 시간 내 수락하지 않음
  - 기사 취소
  - 위치 이탈 또는 비정상 상태 감지
  - ETA 급증으로 SLA 위반 가능성 증가
- 재배차 시 기존 기사는 즉시 후보군에서 제외하거나 패널티를 부여한다.
- 재배차 횟수가 임계치를 넘으면 자동 배차를 중단하고 수동 처리로 전환한다.

## 기사 점수
- 기사 점수는 추천 기사 선별과 자동 확정에 사용한다.
- 예시 평가 요소
  - 최근 수락률
  - 최근 취소율
  - 평균 픽업 도착 시간
  - 운행 완료율
  - 고객 평가
  - 현재 공차 거리
  - 연속 배차 횟수
- 점수는 고정값이 아니라 운영 정책에 따라 가중치를 조정할 수 있다.

## 운행 종료
- 오더가 `COMPLETED` 상태가 되면 기사 상태를 `IDLE`로 전환한다.
- 운행 종료 시 후속 처리
  - 기사/차량 상태 갱신
  - 정산 또는 운행 기록 저장
  - 통계/리포트 데이터 누적
  - 필요 시 고객 알림 발송
- 운행 종료 후 위치 정보가 갱신되면 즉시 다음 배차 후보에 포함될 수 있다.

## 예외 처리
- 기사 위치 미수신: 마지막 위치 기준으로 제한적으로 계산하거나 후보 제외
- 지도 ETA 실패: 대체 추정값 사용 후 낮은 신뢰도 표시
- 모든 기사 배차 실패: `FAILED` 또는 `WAITING`으로 전환
- 중복 수락: 먼저 확정된 기사만 유지하고 나머지는 취소 처리
- 고객 취소: 현재 단계에 따라 배차 취소, 재배차 중단, 기사 상태 복구
- 기사 앱 오류: 일정 시간 응답 없으면 자동 재배차

## 알고리즘
1. 신규 오더 생성
2. 오더 상태를 `WAITING`으로 설정
3. 반경 내 `IDLE` 기사 조회
4. 기사 상태, 차량 상태, 충돌 여부 필터링
5. ETA 계산
6. 기사 점수 및 우선순위 가중치 계산
7. 상위 추천 기사 목록 생성
8. 자동 확정 정책이 있으면 최고 점수 기사에게 배정 시도
9. 실패 시 다음 후보 또는 WAITING Queue로 전환
10. 수락 성공 시 `DISPATCHED` 처리
11. 기사 취소/타임아웃 시 자동 재배차 수행
12. 운행 완료 시 상태 종료 및 후속 처리

## Sequence Diagram
```text
Customer -> Order Service: 오더 생성
Order Service -> Dispatch Engine: 배차 요청
Dispatch Engine -> Driver Pool: 가용 기사 조회
Driver Pool -> Dispatch Engine: 후보 기사 목록 반환
Dispatch Engine -> ETA Service: 이동시간 계산
ETA Service -> Dispatch Engine: ETA 반환
Dispatch Engine -> Scoring Engine: 기사 점수 계산
Scoring Engine -> Dispatch Engine: 점수 결과 반환
Dispatch Engine -> Driver App: 상위 기사 배차 제안/확정
Driver App -> Dispatch Engine: 수락 또는 거절

alt 수락 성공
    Dispatch Engine -> Order Service: DISPATCHED 상태 갱신
    Order Service -> Notification Service: 고객/운영자 알림
else 수락 실패
    Dispatch Engine -> Waiting Queue: 재시도 또는 대기열 등록
    Waiting Queue -> Dispatch Engine: 재배차 트리거
end

Dispatch Engine -> Order Service: COMPLETED 상태 갱신
Order Service -> Driver Pool: 기사 상태 IDLE 복구
```

# GIT

## 브랜치 전략
- `main`: 배포 가능한 안정 브랜치
- `feature/*`: 기능 개발 브랜치
- `fix/*`: 버그 수정 브랜치

## 커밋 원칙
- 한 커밋은 하나의 목적만 담는다.
- 의미 있는 단위로 자주 커밋한다.
- 예시
  - `feat: add login flow`
  - `fix: resolve blade layout component path`
  - `docs: add project documents`

## Pull Request
- 변경 내용 요약
- 테스트 여부
- 화면 변경 시 스크린샷 첨부
- 관련 문서 업데이트 여부 확인

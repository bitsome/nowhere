## ⑤ 마스터 관점의 우선순위·다음 행동 추천

1. **HTTPS 고정 주소 확보(최우선 · 사용자 전용)** — 유입 장치(랜딩·공유 링크)를 전부 만들어 두고도 **주소가 매번 바뀌어 링크가 죽는 상태**다. 도메인 + SSL 또는 Named Tunnel이 확정되기 전까지 홍보는 실효가 없다.
2. **첫 수익 실현 1건** — 이제 **스케줄러가 살아 있어 자동 정산이 실제로 돈다**(Task 11). 실제 등록자 운행 1건 → 완료 → 자동 정산 → 입금 → 수금 확인 → 수수료 매출 반영까지 한 번 통과시키면 프로젝트가 '수익 발생'을 실증한다. `DEN-` 재고 정리를 선행.
3. **미커밋 90건 커밋**(사용자 지시 후) — Task 4~14와 UI 개선분이 아직 어디에도 기록되지 않았다. **운영에서만 드러나는 결함을 세 번(500·스케줄러·데이터) 겪은 구간**이라 되돌림 지점 확보가 특히 중요하다.
4. **운영 스모크 재실행 + 배포 절차 고정** — `smoke_endpoints.sh`(GET 35개)·`verify_api_contract.sh`·`rehearse_external_surface.ps1`을 **배포 필수 단계로 규칙화**하고, 스케줄러 동작 모니터링(로그·알림)을 추가한다.
5. **문서 정합(Q-6)** — CHANGELOG에 Task 4~14 추가, ORDER_FLOW 수금 상태, OPERATIONS 입금/수금 단계, TASKS `Current` 갱신. **13회차 누적 불일치.**
6. **공유 링크 정책 마감** — 토큰 만료·회수/재발급 + 유입 계측(`behavior_events`) 연결. 유입 장치를 만들었으니 **효과 측정 경로**가 있어야 다음 판단이 가능하다.
7. **랜딩 유입 경로 확정** — 루트(`/`) → `/welcome` 리다이렉트 vs 홍보 링크 고정 + Blade 안내 문구 정합 (7회차 누적).
8. **A-5 불일치 종결(13회차)** — `:show-match-reasons` 한 줄 추가 vs IMPROVEMENT_PLAN L162 문서 정정. 매 검토마다 재발견되므로 이번에 끝낼 것을 권장.
9. **공개 payload 문구·테스트 정합** — `row.id`/`key` 노출 유지 여부를 결정하고, 유지라면 spec·테스트 문구를 실제와 맞춘다.
10. **접근성·배지 표준 결정** — `:focus-visible` 포커스 링(`outline: none` 16곳) · `n-badge` 색/크기·글자색 대비 규약 · `transition` 전역 감소 범위 · 라이트 그라디언트 2모드 통일.
11. **다음 블록 확정** — 수익 축 확장(플랜 등급·PG 자동 수금) vs 품질 블록(Q-3 CI·Q-5) (사용자 지시 대기).

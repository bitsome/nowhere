## (c) 발견한 개선 포인트
1. **앱 전체 `!important` 2곳이 형제 규칙 하나를 이기기 위해 사용 중(신규 발견·적용)**: 댓글 시간 `.comment-row__time` 은 muted 색·11px 를 적용하려고 `color`·`font-size` **양쪽에** `!important` 를 달고 있었다. 원인은 같은 파일의 `.comment-row span { color: var(--text) }` 로, scoped 컴파일 기준 `.comment-row span[data-v]`(0,2,1) 이 `.comment-row__time[data-v]`(0,2,0) 을 이기기 때문이다. 즉 **"값 문제"가 아니라 "선택자 범위 문제"** 인데도 `!important` 로 덮고 있어, ① 이후 같은 파일에 muted 시간 규칙을 추가하려는 사람이 또 `!important` 를 쓰게 되고 ② 앱 CSS 규약(라이브러리 컴포넌트 덮어쓰기 외 `!important` 미사용)의 유일한 예외가 남는다. 선택자를 `.comment-row span.comment-row__time` 으로 좁히면 (0,3,1) 로 경쟁 규칙을 정상적으로 이긴다.
2. **템플릿 3대 계약은 전부 정합(신규 전수 검증)**: ① `v-for` 195건 ↔ `:key` 195건이 **파일별로 정확히 일치**(누락 0) ② `<button` 248건 대비 `type` 지정 254건으로 **무타입 버튼 0건** ③ EmptyState 사용처 전부 `title` 지정으로 **기본값 "데이터가 없습니다" 노출 0건**. 세 축 모두 이전 회차에 전수 감사 기록이 없어 이번에 처음 닫았다.

## (f) 빌드 결과
- **`npm run build` 통과** (vite v8.2.1, `✓ built in 1.01s`, 오류·경고 0건) — 수정 반영 후 실행. `CommunityView`·`CommunityPostView` 청크 정상 재생성.

- 빌드 산출물 검증: 2개 CSS 청크(`CommunityView-*.css`·`CommunityPostView-*.css`)에 `.comment-row span.comment-row__time` 반영 확인, `!important` 는 `frontend/src` 전체 0건.
- 서버 배포·빌드·DB 동기화는 수행하지 않음(로컬 작업만). 적용분은 워킹트리에 남김(사용자 커밋 대기).

## (c) 발견한 개선 포인트
1. **무한 반복 펄스 6곳 중 6곳이 모션 감소 미대응(신규 발견·적용)**: 앱은 이미 스켈레톤 shimmer에 `@media (prefers-reduced-motion: reduce)` 정지 규칙을 두고 있는데, **사용자 행동과 무관하게 계속 깜빡이는 장식 모션**(신규/추천 카드 배경 펄스, 임박 배지 그림자 펄스, 운행중 표시 점멸)에는 같은 규칙이 **하나도 적용돼 있지 않았다**. 특히 `.order-card--highlight`·`.set-card--highlight`는 **추천 카드가 화면에 머무는 동안 무한 반복**되고, `.hb-driving__dot`은 **운행중 화면 전체에서 계속 점멸**한다. 모션 민감 사용자(어지럼·전정 장애)에게 상시 노출되는 요소이며, OS의 "동작 줄이기" 설정을 켠 사용자에게도 앱만 무시하는 상태였다.
2. **자매 카드의 동일 배지가 서로 다른 빨강 그림자를 사용(신규 발견·적용)**: `.order-card__urgent`와 `.set-card__urgent`는 padding·radius·폰트·`letter-spacing`·배경(`var(--danger)`)·다크 글자색 예외까지 완전히 같은 규격인데, **그림자만** OrderCard는 `color-mix(in srgb, var(--danger) …)`, SetGroupCard는 하드코딩 `rgba(229, 72, 77, …)`(= `#e5484d`)를 쓴다. 라이트에서 `--danger`=`#b42318`이므로 **같은 목록의 단일 카드/셋트 카드 임박 배지가 서로 다른 색으로 번지고**, 다크(`#d86262`)에서는 격차가 더 벌어진다. 배경은 토큰인데 그림자만 다른 빨강이라는 점에서 규칙 내부 자기모순이기도 하다.
3. **모션 감소 규칙을 base.css 전역에 넣을 수 없는 구조적 이유 확인(기술 근거)**: SFC `<style scoped>` 는 셀렉터를 `.class[data-v-xxxx]`(명시도 0,2,0)로 컴파일하므로, base.css에 `.class`(0,1,0)로 적은 미디어 쿼리는 **명시도에서 지고 무효**가 된다(공용 스켈레톤은 base.css 자체 정의라 성립). 따라서 이번 교정은 **각 컴포넌트 scoped 블록 내부, 해당 `animation` 선언 이후 위치**에 배치했다 — 이는 [OrderCardSkeleton.vue](file:///d:/wwwroot/nowhere/frontend/src/components/orders/OrderCardSkeleton.vue#L75-L80)의 기존 방식과 동일하다.
4. **일회성 등장 애니메이션·스피너는 의도적으로 미적용(후보)**: `card-highlight-in`·`set-highlight-in`(0.4s 슬라이드인)은 `.order-card--highlight`/`.set-card--highlight`의 `animation` 단축 속성에 **묶여 있어** 이번 `animation: none` 으로 함께 사라진다(요소는 자연 상태인 opacity 1·translateY 0 로 정착하므로 시각 결함 없음 — 의도된 결과). 반면 `notify-in`·`nav-badge-pop`·`celebration-burst/pop` 는 1회성이라 WCAG 2.2.2 대상이 아니고, 스피너(`ig-spin` 등)는 **로딩 진행 상태를 전달하는 정보성 모션**이라 정지시키면 오히려 "멈춘 화면"으로 오인될 수 있어 유지했다.
5. **`transition` 전역 감소는 미적용(후보)**: 호버·탭 전환 등 광범위한 `transition` 을 모션 감소 시 0으로 만들면 화면 전반의 피드백이 사라진다. 별도 판단이 필요한 전역 설계 사안으로 후보 기록.

## (e) 적용하지 않은 항목과 이유 (후보)
1. **스피너 모션 감소 미적용(`ig-spin`·`cb-spin`·`img-sheet-spin`·`img-sheet-bar-slide`)**: 회전 스피너는 로딩 **진행 상태를 전달하는 정보성 모션**이다. 정지시키면 정지 화면이 "멈춘 것"으로 오인될 수 있고, 스켈레톤 shimmer 정지(기존 규약)와 달리 대체 진행 표시가 없다 → 유지.
2. **일회성 등장 모션(`notify-in`·`nav-badge-pop`·`celebration-burst/pop`)**: 재생 시간이 0.3~1.6초이고 반복되지 않아 WCAG 2.2.2(움직이는 콘텐츠의 일시정지) 적용 대상이 아니다. 축하 연출은 완료 피드백이라는 의미가 있어 유지 → 후보.
3. **`transition` 전역 감소**: 호버·탭·모달 전환 등 앱 전역 피드백이 사라지는 부작용이 커, `transition-duration` 축소 범위를 정하는 **전역 설계 결정**이 선행돼야 한다 → 후보.
4. **`OrderDetailView` `.hero-badge--urgent` 의 `#e5484d`·`rgba(229, 72, 77, …)` 하드코딩**: 이 배지는 **배경과 펄스 그림자가 같은 빨강(`#e5484d`)** 이라 규칙 내부는 일관적이다. 셋트 카드처럼 배경만 `--danger` 로 바꾸면 오히려 시각이 달라지므로, "의미색 하드코딩" 계열 전역 과제로 남긴다 → 후보.
5. **`:focus-visible` 미정의 다수 + `outline: none` 16곳**: OrderCard·SetGroupCard 2곳만 키보드 포커스 링을 갖고 나머지 입력·버튼은 `outline: none` 으로 제거돼 있다. 다만 이 앱은 모바일 터치 중심이고, 포커스 링 색·굵기를 정하는 **전역 접근성 스타일 결정**(색 대비 기준 포함)이 필요해 후보로 기록.
6. **FAB 3곳(`var(--brand)` + 흰 글리프)**: 아이콘 관용 + 전역 brand 위 글자색 설계 결정 건으로 09-03~09-10 여러 회차에서 반복 분류된 항목 → 기존 분류 유지(반복 미적용).
7. **관리자 화면 상태 칩 잔여분(AdminView 6곳 — 1px 8px·2px 8px / 700)**: 정보 밀도가 높은 운영 도구로 굵은 칩이 의도된 구분일 수 있어 기사 앱 화면 우선 원칙에 따라 후보 유지.
8. **`assets/base.css` 레거시 `.card`·`.btn` 계열(465~534행)**: 사용처 0건으로 확정된 죽은 CSS. UI 개선이 아닌 정리 작업이고 동적 클래스 결합 가능성을 배제할 수 없어 후보 유지.
9. **기존 반복 후보(18:01·17:01·16:02·15:01 기록분 유지)**: 커뮤니티 카테고리 색 체계 · "내 마켓" 아이콘 표기 불일치 · MoreView 정산/처리할 일 아이콘 중복 · 하위 화면 뒤로가기 중복 · 앰버 팔레트 3종(`#f0a800` vs `--warn` #ffa940 vs `--status-acceptance-pending` #c28a2e) · 말줄임표 ASCII/`…` 혼재 · 모달 푸터 '닫기'/'취소' 혼재 · AdminView 금액 인라인 포맷 · HomeView `.home-more` 공통화 · SettlementView 계좌 마크업 중복 · SettingsVehiclesView 로딩 스켈레톤 부재 · 공유 크롤러 Blade 링크 색(`#36adff` on `#f4f4f4`, 대비 ≈2.2:1 — Blade 공개 페이지 링크 색 규약 미정) — 기존 분류 유지.

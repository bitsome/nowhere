## (e) 적용하지 않은 항목과 이유 (후보)
- **다크 모드 primary/아바타 흰 글자 대비 (MessageBubble·ChatList·ChatRequestSheet/Event·ChatImageSheet·SettingsView·AdminView·OrderCreateView 등 10여 곳)**: 전역 `--on-brand`(브랜드 위 텍스트색) 토큰 설계가 필요. 파일별 부분 수정 시 불일치 발생. 전역 결정 후 일괄 적용 대상.
- **SettingsVerificationView "신청" primary 2개 중복**: 행 단위 보조 액션 재설계 필요(단순 타입 변경 시 주동작 시각 약화).
- **ChatList 타입 칩 의미-색상 불일치(`--green`이 라이트에서 파랑) + yellow/red 라이트 대비**: 타입별 시맨틱 색 체계 설계 판단 필요.
- **AdminView `.auto-history__status` 흰 글자 on 밝은 상태색(라이트)**: RideHistory의 statusTextColor 헬퍼 유형 적용이 필요한 색상 체계 결정.
- **OrderCreateView `.cal__day--today` 다크 틸 배경+흰 글자**: 위 1번(브랜드 위 텍스트)과 동일 설계 의존.
- **EmptyState 아이콘 5색 하드코딩**: 무의미한 색상 강조. grayscale 통일 여부는 디자인 결정.
- **DashboardView `.dash-upcoming__card--today/--tomorrow` rgba 그라디언트**: 값이 상태색과 동일 계열이나 알파값이 달라 변수/color-mix 전환 시 설계 검증 필요.
- **data/levels.js 레벨 타이틀 "드라이버"→"기사"**: 주석상 백엔드 LevelTable과 동기화된 값 — 교차 변경 필요.
- **OrderCard 남은 시간 색 4종(#18a058/#ffa940/#f0a800/#13c2c2)**: 다크 오버라이드 값이 변수 값과 달라 토큰화 시 색 변화 발생. 긴급도 색상 개선(3시간 미만 틸→레드)과 함께 재검토.
- **VerifiedBadge `#1f9d63`**: `--status-completed`(#18a058)와 미세한 값 차이. 토큰 통일은 색상 변화 수반.
- **SettingsVehiclesView "기본/검증" n-tag → VerifiedBadge 사용 통일**: 컴포넌트 교체로 화면 변화 범위 큼.
- **OrderCreateView n-card 중첩(스케줄/셋트)**: 중간 규모 구조 변경.
- **SettingsAppearanceView 스위치 설명 문구가 상태와 무관하게 고정**: 동적 문구 전환은 작은 기능 변경.

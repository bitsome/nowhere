## (c) 발견한 개선 포인트
1. **`color-scheme` 미선언으로 다크 모드에서 네이티브 UI만 라이트로 남음(신규 발견·적용)**: 앱은 `html.dark` 클래스와 토큰으로 색을 뒤집지만, **브라우저가 직접 그리는 요소는 CSS 토큰을 읽지 않는다**. `color-scheme` 이 없으면 스크롤바·날짜/시간 피커·파일 버튼·autofill 배경은 계속 라이트로 그려져, 다크 모드에서 ① 페이지와 13개 스크롤 컨테이너의 스크롤바가 밝은 회색으로 남고 ② 운행 필터의 출발일시 피커(캘린더)와 운행 요청 시트의 시간 입력 피커가 흰 팝업으로 뜬다. 구현은 두 줄이지만 **앱이 못 그리는 영역이라 "다크 모드인데 여기만 밝다"는 원인을 찾기 어려운 유형**이다.
2. **모바일 동적 뷰포트(`dvh`) 미적용 잔여 3곳(신규 발견·적용)**: 09-07 회차에서 인증 3화면만 `100dvh` 로 바뀌었고, 그 화면들을 감싸는 앱 셸은 `min-height: 100vh`, 가장 자주 쓰는 바텀시트 2종은 `max-height: 82vh` 로 남아 있었다. `vh` 는 **주소창이 숨겨진 최대 높이** 기준이라 주소창이 보이는 상태에서는 실제 화면보다 크다 → 앱 셸은 짧은 화면에서도 항상 주소창 높이만큼 빈 스크롤이 생기고, 시트는 하단 둥근 모서리·safe-area 패딩이 화면 밖으로 밀릴 수 있다.
3. **오버레이 내부 스크롤의 체이닝(신규 발견·적용)**: 시트 내부 목록(`.rq-menu`·`.rq-form`·`.img-sheet__body`)에 `overscroll-behavior` 가 없어, 목록 끝에서 계속 스와이프하면 뒤 화면이 따라 스크롤되고 모바일 PWA의 당겨서 새로고침이 걸릴 수 있다. 저장소에는 칩 가로 스크롤용 `overscroll-behavior-x: contain` 선례만 있어 **패턴이 있으나 세로 스크롤 영역에는 미적용**이었다.

## (e) 적용하지 않은 항목과 이유 (후보)
1. **PWA 매니페스트 용어 위반(4번)**: "드라이버 오더 마켓 / 오더 등록·수주" → "기사 운행 마켓 / 운행 등록·수주" 로 고치는 것이 규칙에 맞지만, `frontend/src` 밖 파일이고 제품 소개 문구(현재 "마켓" 중심 ↔ 본문은 "운행 최적화 플랫폼")를 함께 정할 사안이라 후보로 기록. 앱 이름이 설치 프롬프트에 노출되므로 **다음 회차 우선 처리 권장**.
2. **`theme-color`·매니페스트 색의 테마 연동(5번)**: 다크 모드에서 주소창·스플래시가 밝게 남지만, 메타 갱신 로직을 `theme.js` 에 추가하는 **동작 변경**이고 어떤 색(브랜드 vs 배경)을 쓸지 결정이 필요 → 후보.
3. **`aria-live` 도입(6번)**: 토스트·새 메시지·저장 완료를 스크린리더에 알리는 접근성 개선이지만 라이브 영역 컨테이너 신설·토스트 구조 분리가 필요해 이번 "선언 추가" 범위를 넘는다 → 후보.
4. **`user-scalable=no`(7번)**: 확대 허용은 접근성에 유리하나 앱 모양(고정 레이아웃)과 확대 시 레이아웃 대응이 함께 검토돼야 하는 제품 결정 → 후보.
5. **아바타(`--accent`) 흰 이니셜**: 직전 회차의 `--brand-gradient` 교정과 같은 증상(다크 틸 위 흰 글자)이지만, `2026-09-07_1006.md` 가 **"아바타 관용 — 임의 수정 금지 대상"** 으로 명시 분류해 두었으므로 이번에도 의도적으로 미적용(분류 유지).
6. **관리자 모달 `60vh`/`50vh`·MarketView `n-drawer` `80vh`**: 관리자 화면은 데스크톱 사용이 중심이고, 드로어는 naive-ui `height` prop 이라 `dvh` 전환 이득이 작다 → 후보.
7. **나머지 기존 반복 후보(8번)**: 전역 디자인 결정 또는 순수 정리 작업 성격으로 09-03~09-10 여러 회차에서 분류된 항목 → 기존 분류 유지(반복 미적용).

# NoWhere — 전체 개선 로드맵·현황 단일 문서 (IMPROVEMENT PLAN)

> **목적**: 제품 문서(PRODUCT\_VISION · OPERATIONS · ORDER\_FLOW · RECOMMENDATION · UI · SECURITY) 대비 **구현 안 된 것 / 분야별 현재 상태 / 실행 로드맵 / 추가 갭**을 한 파일에서 체계적으로 관리한다.
> **사용법**: 항목은 `[ ]`(미진행) / `[~]`(진행 중) / `[x]`(완료). 작업 완료 후 CHANGELOG.md·daily-review 기록 + 본 문서 체크 해제.
> **진단 기준**: 문서 3종 + 프런트/백엔드 코드 전수 감사 (2026-09-05). 코드로 확인된 근거는 파일·라인으로 인용. 검증되지 않은 개선은 `(제안)`으로 표기.

## 0. 핵심 결론

- **완성된 것**: 운행 루프(등록→공개→가져오기/요금제안→승인→운행 6단계→완료→정산 상태 전환→리뷰)와 채팅·알림·웹푸시·커뮤니티·매칭 백엔드. Phase A 전부 + 신고/분쟁 접수·처리(B-1) + 관리자 개입(B-2: 사용자 제재·운행 숨김/보류/강제취소·채팅 중재·정산 보류·일일 운영 화면) + 증빙 심사(B-3: 차량/면허 사진 업로드 → 관리자 승인/거절 → 인증 반영·결과 알림) + 고객지원(B-4: 공지·FAQ·1:1 문의 작성/답변·알림).

- **부족한 것**: 루프 "바깥" — 행동 데이터, 자동화(스케줄러), 품질/기반.

## 2. 구현 안 된 것 (확정 목록 · 코드 근거)

### 2-1. 전면 미구현 (❌)

- [ ] **기사 정산·출금**: 정산 원장·수수료·계좌·출금 테이블/API 0건. `settled` 전환(`OrderTransitionService.php` L179-198)과 조회(`DriverService.php` L125-174)만 존재.

- [ ] **상태 변경 타임라인 저장**: 상태 변경 시각은 `orders` 컬럼 최종값만(`OrderTransitionService.php` L81-105). 이력 테이블·로깅 없음. 프런트 `.status-flow` CSS(OrderDetailView)는 미사용.

- [ ] **신고/분쟁**: report/dispute/blind/ban 관련 코드 0건.

- [ ] **운행 숨김·보류·강제취소·관리자 개입**: 등록자 공개→초안 회귀만이 유일한 비공개 수단. Admin은 기사 상태·자동등록에 한정.

- [ ] **가입 역할 선택**: `AuthController.php` 회원가입 role=Driver 고정(L32), `RegisterView` 역할 UI 없음.

- [ ] **채팅 요청 확정 처리**: `ChatService`는 요청 카드 생성만(L349-363). approval 외 time/route/payment/cancel 확정 API 없음.

- [ ] **고객지원(공지/FAQ/문의)**: 라우트·뷰·메뉴·문자열 전무.

- [ ] **증빙 심사**: 차량/면허 boolean 토글만(`VerificationController`) — 업로드·대기 없음.

- [ ] **항공편·주차·여행지 API**: `return-routes` 외 부가 도구 없음(항공 필드는 데이터 입력용).

- [ ] **행동 데이터 트래킹**: 추천 노출/클릭·신청/거절 로그 없음.

- [ ] **자동 정산 생성·정산 알림**: 완료 후 스케줄러 없음.

- [ ] **비밀번호 찾기/재설정**: 알림 모델만 존재, 라우트 없음.

### 2-2. 부분 구현 (🔶) — 완성 필요

- [ ] **자동 만료**: 30분 미승인 claim은 "접근 시 판정"(`OrderClaimService.php` L32) + 프런트 `withdraw-expired` 호출만. **백그라운드 스케줄러 없음**(routes/console.php는 리마인더·자동등록 2건뿐).

- [ ] **매칭 알림**: `matchForOrder`는 preference 점수>0 기사에게 알림. "조건을 실제 충족한 기사 + 일정 비충돌 + 온라인" 필터 고도화 여지.

- [ ] **검증 인프라**: CI·E2E·커버리지 없음.

- [ ] **보안**: 역할/권한 모델 정리(Spatie 검토), 보안 헤더, 로그인 잠금.

- [ ] **실시간**: SSE는 "안읽음 카운트 감시형"(20초 자동 종료), 채팅은 3초 폴링. 웹소켓/브로드캐스팅 미도입.

## 6. 우선순위 판단 기준 · 실행 규칙

1. **판단 기준**: 고객(기사/등록자) 직접 가치(돈·신뢰·이유) > 운영 안정성 > 데이터/개인화 > 부가 기능.
2. **작업 단위**: 설계 → 구현 → 테스트(Pest/vitest) → 빌드 → CHANGELOG 기록 → 본 문서 체크 해제.
3. **전제**: 모든 개발·검증은 로컬에서만. 서버 배포·DB 동기화는 사용자 명시 지시 시에만.
4. 시작 순서: **A-1(가입 역할)** → A-2 → A-4(타임라인) → A-3(정산·출금) → A-5(근거 노출).

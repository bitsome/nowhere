# SECURITY

> 상태: ✅ 현행 — 인증은 Sanctum Bearer 토큰(SPA API) 기준. (구식 세션 방식 문서 내용은 정리됨)

## 기본 원칙
- 민감한 값은 코드에 하드코딩하지 않는다.
- 모든 비밀번호는 해시 처리된 값만 저장한다.
- 인증과 권한 검사는 서버 기준으로 처리한다.

## 인증
- SPA API는 **Laravel Sanctum Bearer 토큰**을 사용한다 — 모든 요청에 `Authorization: Bearer {token}` 헤더.
- 로그인/회원가입 시 신규 토큰을 발급하고, 로그아웃 시 해당 토큰을 폐기한다.
- SSE는 EventSource가 헤더 인증을 못 하므로 `?token=` 쿼리로 인증한다.
- 비밀번호는 `bcrypt` 해시로만 저장·검증한다.

## 입력 검증
- 모든 폼 입력은 `FormRequest` 또는 검증 로직으로 검증한다.
- 신뢰할 수 없는 입력은 그대로 DB 또는 뷰에 사용하지 않는다.
- 검색, 정렬, 필터 조건은 허용 목록 기반으로 제한한다.

## CSRF / XSS
- SPA API는 Bearer 토큰 인증을 사용하므로 폼 CSRF 토큰이 필요 없다.
- (Blade 레거시 웹 폼 유지 시에만) CSRF 보호를 적용하고 `{{ }}` 이스케이프 출력을 유지한다.
- 사용자 입력을 HTML로 출력하는 경우만 제한적으로 raw 출력을 사용한다.

## 접근 제어
- 인증이 필요한 화면과 API는 `auth:sanctum` 미들웨어를 적용한다.
- 관리자 기능은 별도 권한 정책 또는 게이트를 적용한다.
- 리소스 단위 권한 검사를 누락하지 않는다.

## 운영 보안
- `.env`는 저장소에 커밋하지 않는다.
- 프로덕션에서는 디버그 모드를 비활성화한다.
- 로그에 비밀번호, 토큰, 개인정보를 남기지 않는다.
